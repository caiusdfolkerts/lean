# Nested measurements of eight original graph blocks

One Ubuntu 24.04 runner compiles the frozen sources for eight consecutive row-29 block theorems. It verifies each original theorem’s exact `Block lo hi` type, then exports and checks three nested scopes. The first contains the generic soundness theorem, the second the original block 0528, and the third all eight original block theorems 0527 through 0534. The eight-block module contains only imports. Every mathematical source and certificate sidecar is byte-identical to the complete lower-bound candidate. The Lean and NanoDa executables each check all three exports on this same runner. The single-block and generic export hashes must match the preceding verified-family source diagnostic.

The eight-block group covers 140 ordered keys in one graph row. Timings and peak resident memory measure fixed common costs and additional work across these blocks. The complete Theorem 2, Corollary 4 and minimum-vertex statement require 1,056 graph blocks and additional proof families. This ordinary diagnostic produces no Palomar verdict.

The job has a 170-minute limit, with 8 minutes for Lean setup and 30 for the source build, statement checks and three exports. Up to three one-thread Lean processes compile the source with 4,096 MiB per managed compiler heap. The host’s default cgroup also applies. Each measured process has a 14 GiB address-space limit, a 512 MiB single-file limit and bounded output capture. The independent replay limits in seconds are 1,200 and 480 (generic), 1,500 and 480 (single), and 3,000 and 960 (eight), in Lean and NanoDa order. The six replays run sequentially, each with its own one-MiB-or-smaller receipt. A timed-out replay is reported as censored at its actual limit. Each fixture retains at most 8 KiB of console text in memory and records at most 4 KiB per failed invocation. Receipt artifacts expire after five days. Compiled dependencies and proof exports reside on the ephemeral runner.
